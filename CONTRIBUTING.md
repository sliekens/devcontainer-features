# Contributing

This document explains how to create, test, and publish dev container features.

## Prerequisites

Install the required tools:

```bash
# Dev Container CLI (required for testing and packaging)
npm install -g @devcontainers/cli

# ORAS CLI (required for publishing to OCI registries)
# See: https://oras.land/docs/installation

# jq (required for JSON processing in publish script)
# Install via your package manager (apt, brew, etc.)
```

## Repository Structure

```
my-devcontainer-features/
├── README.md               # Feature collection overview
├── CONTRIBUTING.md         # This file
├── .devcontainer/          # Dev container for working on features
│   └── devcontainer.json
├── scripts/
│   ├── publish.sh          # Publish features to the registry
│   └── test.sh             # Run feature tests
├── src/
│   ├── <feature-id>/       # One directory per feature
│   │   ├── devcontainer-feature.json  # Feature metadata (required)
│   │   ├── install.sh                 # Installation script (required)
│   │   ├── NOTES.md                   # Additional notes (optional)
│   │   └── ...                        # Other files included in package
│   └── ...
└── test/
    ├── <feature-id>/       # Tests for each feature
    │   ├── test.sh         # Default test script
    │   └── scenarios.json  # Additional test scenarios (optional)
    └── _global/            # Global test scenarios
```

## Creating a New Feature

### 1. Create the Feature Directory

```bash
mkdir -p src/my-feature
```

### 2. Create `devcontainer-feature.json`

This file defines the feature metadata. Required fields: `id`, `name`, `version`.

```json
{
    "id": "my-feature",
    "name": "My Feature",
    "version": "1.0.0",
    "description": "A brief description of what this feature does",
    "options": {
        "version": {
            "type": "string",
            "default": "latest",
            "description": "Version to install"
        }
    },
    "installsAfter": [
        "ghcr.io/devcontainers/features/common-utils"
    ]
}
```

See the [full schema](https://containers.dev/implementors/features/#devcontainer-feature-json-properties) for all available properties.

### 3. Create `install.sh`

The installation script runs as root during container build. Options are passed as environment variables (uppercased).

```bash
#!/bin/sh
set -e

echo "Activating feature 'my-feature'"

# Options are available as environment variables
VERSION=${VERSION:-latest}

echo "Installing version: $VERSION"

# Available environment variables:
# $_REMOTE_USER - The configured remoteUser
# $_REMOTE_USER_HOME - Home directory of remoteUser
# $_CONTAINER_USER - The container user
# $_CONTAINER_USER_HOME - Home directory of container user

# Your installation logic here
apt-get update
apt-get install -y some-package

echo "Feature 'my-feature' installed successfully"
```

### 4. Create Tests

Create `test/<feature-id>/test.sh`:

```bash
#!/bin/bash
set -e

# Import test library
source dev-container-features-test-lib

# Run checks
check "my-feature is installed" bash -c "which my-command"
check "my-feature works" bash -c "my-command --version"

# Report results
reportResults
```

For additional test scenarios, create `test/<feature-id>/scenarios.json`:

```json
{
    "custom-scenario": {
        "image": "ubuntu:22.04",
        "features": {
            "my-feature": {
                "version": "2.0"
            }
        }
    }
}
```

## Testing Features

### Test All Features

```bash
./scripts/test.sh
```

### Test a Specific Feature

```bash
./scripts/test.sh my-feature
```

### Test Against a Specific Base Image

```bash
./scripts/test.sh my-feature -i ubuntu:22.04
```

### Manual Testing with Dev Containers CLI

```bash
# Generate and run autogenerated tests
devcontainer features test --features my-feature --skip-scenarios .

# Run scenario tests only
devcontainer features test --features my-feature --skip-autogenerated .

# Test against a specific image
devcontainer features test --features my-feature -i mcr.microsoft.com/devcontainers/base:ubuntu .
```

## Publishing Features

### Publish All Features

```bash
./scripts/publish.sh
```

### Publish a Specific Feature

```bash
./scripts/publish.sh my-feature
```

### Custom Registry

Override the default registry:

```bash
REGISTRY=my-registry.example.com NAMESPACE=my-namespace ./scripts/publish.sh
```

### What Happens During Publishing

1. **Package**: Each feature is packaged into a `.tgz` archive
2. **Push**: The archive is pushed to the registry with version tags:
   - `<major>` (e.g., `:1`)
   - `<major>.<minor>` (e.g., `:1.0`)
   - `<major>.<minor>.<patch>` (e.g., `:1.0.0`)
   - `:latest`
3. **Collection Metadata**: A `devcontainer-collection.json` is generated and pushed

### Idempotency

The publish script checks if a version already exists before pushing. If the exact version is already published, it skips that feature. To republish, bump the version in `devcontainer-feature.json`.

## Versioning

Features follow [semantic versioning](https://semver.org/):

- **MAJOR**: Breaking changes (e.g., removed options, changed behavior)
- **MINOR**: New features, backward-compatible
- **PATCH**: Bug fixes, backward-compatible

To release a new version, update the `version` field in `devcontainer-feature.json` and run the publish script.

## Registry Authentication

The default registry (`ghcr.io`) does not require authentication.

For registries that require authentication, you can:

### Option 1: Docker Credential Store

```bash
# Log in to the registry (credentials are stored securely)
docker login my-registry.example.com

# oras will use Docker's credential store automatically
```

### Option 2: oras login

```bash
oras login my-registry.example.com
```

### Option 3: Environment Variables

```bash
export ORAS_USERNAME=myuser
export ORAS_PASSWORD=mypassword
./scripts/publish.sh
```

## Best Practices

1. **Keep features focused**: Each feature should do one thing well
2. **Support multiple distros**: Handle apt, yum, apk, etc. or document limitations
3. **Use `installsAfter`**: Declare soft dependencies for proper installation order
4. **Provide sensible defaults**: Options should work out-of-the-box
5. **Document options**: Add descriptions to all options
6. **Write tests**: Cover default options and common scenarios
7. **Follow the spec**: See [containers.dev](https://containers.dev/implementors/features/)

## Troubleshooting

### "devcontainer: command not found"

Install the CLI:
```bash
npm install -g @devcontainers/cli
```

### "oras: command not found"

Install oras from https://oras.land/docs/installation

### Tests fail with Docker permission errors

Ensure your user is in the docker group or use sudo:
```bash
sudo usermod -aG docker $USER
# Log out and back in
```

### Feature not found after publishing

1. Check that the registry is accessible
2. Verify the feature was published: `oras manifest fetch ghcr.io/sliekens/devcontainer-features/my-feature:latest`
3. Check for typos in the feature reference
